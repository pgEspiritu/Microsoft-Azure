- **Azure portal** → Provides a web-based interface for creating and managing Azure resources.
- **Azure Cloud Shell** → Provides browser-based **Azure CLI** and **PowerShell**, allowing you to manage Azure resources from supported devices.

**Exam tip:**

**Create/manage Azure resources → Azure portal or Azure Cloud Shell**

**Power Apps → Build business applications**

Therefore, the solution **does not meet the goal**.

**Answer: No.**

- **Azure Key Vault** — Securely stores and manages secrets, keys, and certificates; it does not filter network traffic.

**Exam tip:**

**Control network traffic/ports → Network Security Group (NSG)**

## 107. Your Azure environment contains multiple Azure virtual machines. You need to ensure that a virtual machine named VM1 is accessible from the Internet over HTTP. Solution: You modify a Network Security Group (NSG). Does this meet the goal?

- Yes.
- No.

**Answer:** Yes.

**Explanation:** An **Azure Network Security Group (NSG)** can control inbound and outbound network traffic to Azure resources. To allow VM1 to be accessed over HTTP from the Internet, you can create or modify an inbound security rule to allow **TCP port 80**.

**Why the answer is Yes:**

- HTTP uses **TCP port 80**.
- An NSG can contain inbound security rules.
- An inbound rule can allow traffic from the Internet to VM1 on TCP port 80.
- The NSG can be associated with the VM's network interface or subnet.

**Example rule:**

```text
Source: Any
Source port: *
Destination: VM1
Destination port: 80
Protocol: TCP
Action: Allow
```

**Exam tip:**

Control access to VM ports → NSG

HTTP → TCP 80

Therefore, modifying the NSG can meet the requirement.

**Answer:** Yes.

- Yes.
- No.

**Answer:** No.

**Explanation:** **Azure Traffic Manager** is a DNS-based traffic routing service. It is used to distribute user traffic across different endpoints based on routing methods such as performance, priority, geographic location, or weighted routing.

Traffic Manager does **not** directly control or open network ports on a virtual machine.

To allow VM1 to receive HTTP traffic from the Internet, you should use a **Network Security Group (NSG)** or an appropriately configured **Azure Firewall** to allow **TCP port 80**.

**Why the answer is No:**

- **Traffic Manager** → Routes DNS requests to appropriate endpoints.
- **NSG** → Controls inbound and outbound network traffic and can allow TCP port 80.
- **Azure Firewall** → Can centrally filter and allow network/application traffic.
- **HTTP** → Uses **TCP port 80**.

**Exam tip:**

**Control VM ports → NSG / Azure Firewall**

**Distribute traffic between endpoints → Traffic Manager**

Therefore, modifying an **Azure Traffic Manager profile does not meet the goal**.

**Answer: No.**
