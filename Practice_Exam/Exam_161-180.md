## 161. Your Azure environment contains multiple Azure virtual machines. You need to ensure that a virtual machine named VM1 is accessible from the Internet over HTTP. Solution: You modify a Network Security Group (NSG). Does this meet the goal?

- Yes.
- No.

**Answer:** Yes.

**Explanation:** An **Azure Network Security Group (NSG)** controls inbound and outbound network traffic to Azure resources. To make VM1 accessible over HTTP, you can create or modify an **inbound NSG rule** to allow **TCP port 80** from the Internet.

For example:

- **Source:** Internet
- **Destination:** VM1
- **Protocol:** TCP
- **Destination port:** 80
- **Action:** Allow

The NSG must be associated with the VM's **network interface (NIC)** or the **subnet** containing the VM.

**Why the answer is Yes:**

- HTTP uses **TCP port 80**.
- NSGs can allow or deny traffic based on ports, protocols, and source/destination.
- An inbound NSG rule can therefore allow Internet traffic to VM1 over HTTP.

**Exam tip:**

**Allow/deny VM traffic on a specific port → NSG**

**HTTP → TCP port 80**

**HTTPS → TCP port 443**

Therefore, the solution **meets the goal**.

**Answer: Yes.**

## 162. Your Azure environment contains multiple Azure virtual machines. You need to ensure that a virtual machine named VM1 is accessible from the Internet over HTTP. Solution: You modify an Azure Firewall. Does this meet the goal?

- Yes.
- No.

**Explanation:** **Azure Firewall** can control and allow inbound network traffic to Azure resources. You can configure a **DNAT (Destination Network Address Translation)** rule to forward Internet traffic to VM1 over HTTP (TCP port 80).

For example:

- **Source:** Internet
- **Destination:** Azure Firewall public IP
- **Protocol:** TCP
- **Destination port:** 80
- **Action:** DNAT to VM1

Therefore, modifying Azure Firewall can make VM1 accessible from the Internet over HTTP, assuming the required networking and NSG rules also permit the traffic.

**Exam tip:**

**Azure Firewall → Centralized network traffic filtering + DNAT**

**NSG → Allow/deny traffic at subnet/NIC level**

**HTTP → TCP port 80**

Therefore, the solution **meets the goal**.

**Answer: Yes.**

## 163. Your Azure environment contains multiple Azure virtual machines. You need to ensure that a virtual machine named VM1 is accessible from the Internet over HTTP. Solution: You modify an Azure Traffic Manager profile. Does this meet the goal?

- Yes.
- No.

**Answer:** No.

**Explanation:** **Azure Traffic Manager** is a **DNS-based traffic routing service**. It directs client requests to different endpoints based on routing methods such as priority, performance, geographic location, or weighted routing.

Traffic Manager does **not** directly open or allow HTTP ports on a virtual machine.

To allow VM1 to receive HTTP traffic from the Internet, you would typically configure an **NSG inbound rule** allowing **TCP port 80**. An Azure Firewall can also be used as part of a more centralized network security design.

**Why the answer is No:**

- **Traffic Manager** → Routes DNS requests to appropriate endpoints.
- **NSG** → Controls whether traffic such as HTTP/TCP 80 is allowed to a VM.
- **Azure Firewall** → Provides centralized network traffic filtering and can use DNAT for inbound traffic.

**Exam tip:**

**Control VM port access → NSG**

**Centralized firewall/filtering → Azure Firewall**

**DNS-based traffic routing → Traffic Manager**

Therefore, modifying an **Azure Traffic Manager profile does not meet the goal**.

**Answer: No.**

**Exam tip:**
