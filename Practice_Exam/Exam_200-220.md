## 201. Your company has virtual machines (VMs) hosted in Microsoft Azure. The VMs are located in a single Azure virtual network named VNet1. The company has users that work remotely. The remote workers require access to the VMs on VNet1. You need to provide access for the remote workers. What should you do?

- Configure a Site-to-Site (S2S) VPN.
- Configure a VNet-to-VNet VPN.
- Configure a Point-to-Site (P2S) VPN.
- Configure DirectAccess on a Windows Server 2012 server VM.
- Configure a Multi-Site VPN.

**Answer:** Configure a **Point-to-Site (P2S) VPN**.

**Explanation:** An **Azure Point-to-Site VPN** allows individual remote users to securely connect from their computers to an Azure virtual network.

In this scenario:

**Remote worker → P2S VPN → VNet1 → Azure VMs**

P2S is appropriate because the users are connecting **individually from remote locations** rather than connecting an entire on-premises network to Azure.

**Why the others are incorrect:**

- **S2S VPN** → Connects an entire on-premises network to an Azure VNet.
- **VNet-to-VNet VPN** → Connects two Azure virtual networks.
- **DirectAccess** → An older Windows Server remote-access technology and not the appropriate Azure VPN solution here.
- **Multi-Site VPN** → Connects multiple on-premises sites to an Azure VNet.

**Exam tip:**

| Requirement | VPN type |
|---|---|
| Individual remote users → Azure VNet | **P2S** |
| On-premises network → Azure VNet | **S2S** |
| Azure VNet → Azure VNet | **VNet-to-VNet** |
| Multiple on-premises sites → Azure | **Multi-Site** |

**Answer: Configure a Point-to-Site (P2S) VPN.**

**Classify and protect documents / emails → Microsoft Purview Information Protection**

Therefore, recommending **Microsoft Purview Information Protection** does **not** meet the goal.

### 208. You are planning a strategy to deploy numerous web servers and database servers to Azure. This strategy should allow for connection types between the web servers and database servers to be controlled.

**Solution:** You include the Azure Service Bus in your strategy. Does the solution meet the goal?

- Yes.
- No.

**Answer: No.**

**Explanation:** **Azure Service Bus** is a fully managed messaging service used to reliably connect applications and services through **queues and topics**. It is not the appropriate solution for controlling the types of network connections allowed between web servers and database servers.

The appropriate solution is a **Network Security Group (NSG)**.

An NSG allows you to create rules that control **inbound and outbound network traffic** based on factors such as:

- Source and destination IP addresses
- Source and destination ports
- Protocols such as TCP or UDP
- Direction of traffic

For example, you can configure an NSG to allow web servers to connect to database servers only on the required database port.

### Why?

- **Azure Service Bus** → Messaging between applications and services. ❌
- **Network Security Group (NSG)** → Controls and filters network traffic to and from Azure resources. ✅

**Exam tip:**

> **Control network traffic / ports / protocols → NSG**

> **Application messaging / queues / topics → Azure Service Bus**

Therefore, including **Azure Service Bus** does **not** meet the goal.

**Answer: No.**
